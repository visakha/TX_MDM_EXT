## Proposed history tables (recap from FINDINGS.md - NOT BUILT)
- EVT_MASTER_HIST: 1 row per event per master (root fields, states, event meta, payload
  snapshot), valid_from = dateOfChange, valid_to NULL; previous open row for that
  business_id gets valid_to = this dateOfChange.
- EVT_MASTER_PHONE_HIST / EVT_MASTER_SRC_ADDR_HIST / EVT_MASTER_ADDR_HIST /
  EVT_MASTER_ALT_ID_HIST: child rows keyed business_id + child _id, Type 2 the same way;
  a removed child row is closed (valid_to set), never deleted.
- EVT_FIELD_CHANGE: 1 row per dataDiff entry (field_path, child _id, change_type, old, new).
- EVT_MEMBER_HIST: master-source membership, Type 2 (open on ADDED, close on REMOVED).
- EVT_XREF_CHANGE: 1 row per affectedXrefs entry per event.
- All append and close only. No DELETE, no TRUNCATE, no DROP.
